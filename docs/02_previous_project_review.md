# 去年同类项目评审与 2026 要求差距

## 1. 评审结论

去年 Ariadne 项目最有价值的是“采集—标准化—实体图—ATT&CK—Web 可视化”的工程主线，以及 FastAPI、React、Neo4j、Wazuh、Auditd、Zeek 的可演示组合。它适合作为原型和 UI/图查询参考，不适合作为今年系统的直接代码基线。

根本原因是：交付文档的能力陈述明显超出压缩包中的源码和测试证据。实际源码只有后端/前端主体，没有安装文档所列的 `config/`、`deploy/`、`tests/`、`requirements.txt` 和模拟器；`backend/app/core/events.py` 为空，事件在模块间以松散字典传递；前端大量接口失败后返回固定 Mock；APT 画像、历史案例和部分指标是硬编码示例；测试报告明确只使用 5 节点且“不使用预制离线数据集”；PPT 将大模型能力列为未来展望。因此今年必须保留思想、重做契约和验证链。

## 2. 评审材料

- 作品技术原理介绍、概要设计、详细设计、测试分析报告。
- PPT、安装使用文档、任务分工说明。
- 压缩包内全部 Python/React 源码及 Mock 数据。
- 今年官方第 3 题和测试要求。

评审原则是“代码与测试证据优先于报告描述”。文档中出现而代码、配置或测试无法证明的能力，视为设计设想而非已实现能力。

## 3. 可以借鉴的设计思想

| 设计思想 | 借鉴方式 | 今年的改进 |
|---|---|---|
| 端点与网络双侧观测 | 保留 Wazuh/Auditd/Sysmon + Zeek | 增加 Windows Security、登录会话、时间质量和传感器覆盖 |
| 分层 ETL | 保留采集、标准化、解析、入图分层 | 用版本化契约替代自由字典；加入 dead-letter 与 raw archive |
| Neo4j 表达进程链和网络关系 | 保留实体图与变长路径查询 | 会话节点化、关系事件化、证据 ID、有效时间和置信度 |
| ATT&CK 映射 | 保留规则结果映射和矩阵高亮 | 使用固定版本 STIX、Technique ID 主键和映射依据 |
| FastAPI + React | 保留易开发、易演示的前后端分离 | OpenAPI 生成前端类型，接口不再隐式回退 Mock |
| 图谱可视化 | 保留溯源画布、节点下钻 | 限制默认子图规模，以攻击链而非全图作为主视图 |
| 离线降级演示思路 | 保留真实实验快照 | UI 明确标注 Snapshot，不伪装成实时数据 |

## 4. 可以借鉴但需要重构的实现

### 4.1 LogNormalizer

去年 normalizer 已覆盖部分 Zeek conn/dns/http/files 和 Wazuh 内的 Sysmon/Auditd/FIM 字段，说明 adapter 分支方向正确。但其输出是一个宽而松散的字典，缺少 schema 版本、原始证据引用、解析器版本、时间不确定性、host alias、动作结果和字段来源。重构为 `RawEventEnvelope -> UnifiedSecurityEvent`，保留 source-specific 扩展。

### 4.2 ProcessParser 与 NetworkParser

去年能够生成 Process/User/File/IP/Domain 节点及 SPAWNED、CONNECTED_TO 等边，可复用其字段映射思路。必须重构进程身份：Windows 优先使用 ProcessGuid；Linux 使用 `host_id + boot_id + pid + start_time`。不能使用 `host+pid+name` 或把命令行加入稳定身份。网络连接必须以 Session/Zeek uid 保留单次会话，不能把同一 IP 对多次通信聚合成一条覆盖时间的边。

### 4.3 ChainBuilder 与图查询

变长路径和专项查询可作为原型。但硬编码 `192.168.*`、固定端口、可疑进程名单和最大 6 层会造成环境耦合；查询中“路径最长”不等于“攻击最可信”。重构为时间单调、资产边界、会话、告警分数和证据质量共同约束的候选路径搜索。

### 4.4 ATT&CK 与归因

去年把规则标签、进程关键字映射到 Technique，再与少量 APT 技术集合求重合，适合作为 UI 演示原型。需要改为基于 MITRE ATT&CK STIX 固定版本的数据层；APT 输出必须是候选及相似性，区分直接 IOC 命中、基础设施弱关联和 TTP 相似，列出反证，禁止“锁定攻击者身份”的绝对表达。

### 4.5 前端

暗色安全分析界面、攻击图、拓扑、趋势和 ATT&CK 高亮有展示价值。应拆分巨大的 `App.jsx`，让“事件—证据—链—技术—归因”可双向跳转。API 失败时应显示错误或显式 Snapshot 模式，不能静默返回 APT28、固定 IP 和固定攻击链。

## 5. 已经不能满足今年要求的内容

| 今年要求 | 去年材料/源码现状 | Gap |
|---|---|---|
| 大模型多智能体协调 | 源码无 Agent/LLM 模块，PPT 列为未来展望 | 完全缺失 |
| 互联网数据集验证 | 测试报告明确未使用离线数据集 | 完全缺失 |
| 不少于 8 节点及指定角色 | 只验证 5 节点，且没有规定的 firewall/email/internal switch 等完整角色 | 不满足 |
| Windows/Linux 完整覆盖 | 文档声称支持，测试主要是 Linux/Wazuh/Auditd；缺可审计 Windows 场景 | 证据不足 |
| 登录会话重建 | 文档声称基于 sshd，源码没有独立 Session 模型和配对状态机 | 基本缺失 |
| 注册表实体 | normalizer 可读部分 Sysmon 字段，但图模型无 Registry 节点 | 缺失 |
| 内存注入/反射加载 | 文档和 UI 有描述，源码缺完整采集—检测—测试闭环 | 证据不足 |
| DNS/HTTP/ICMP 隐蔽信道 | 主要是 UI 熵值和简单特征，未见三类测试指标 | 不完整 |
| C2 注册/历史/关联域名 | API key 为空，新注册域名始终返回 False | 示例化 |
| 多攻击技术逻辑关联 | 多为若干独立 Cypher 命中后汇总 | 缺少因果/会话关联 |
| 初始入口与数据外传全路径 | 大流量阈值和进程链不能证明“存储到外传” | 不完整 |
| 统一模块契约 | `events.py` 为空，各模块使用自定义 dict | 缺失 |
| 可重复测试 | 压缩包没有 tests 和测试工具，报告所述脚本未随源代码交付 | 无法复现 |

## 6. 不建议继续沿用的设计

- 不沿用“报告先宣称、源码后补”的方式；每项能力必须有 fixture、测试和证据。
- 不沿用将 Neo4j 同时当原始日志库、统计库和配置库的做法；原始事件、任务状态和图谱职责分离。
- 不沿用 `MATCH (n) DETACH DELETE n` 暴露为普通资产重置接口的做法。
- 不沿用前端静默 Mock。演示快照必须显式标识，真实模式请求失败必须可见。
- 不沿用 IP 对单边累加字节的网络模型；它会丢失会话、端口变化和时间历史。
- 不沿用以进程名/命令行关键字直接得出高置信归因的做法。
- 不沿用固定 `192.168.*`、固定路径、固定账号密码和空 API key 的部署假设。
- 不沿用“所有关系 MERGE 后覆盖 timestamp”的写法；行为关系应是可区分的事件实例或 Session。
- 不沿用过度承诺，如“毫秒级”“过滤 90% 噪音”“准确率较高”，除非有测试数据、样本量和测量方法。

## 7. 今年必须新增的能力

1. `contracts/`：七个跨模块模型及 JSON Schema/OpenAPI。
2. 原始事件不可变存档、dead-letter、解析器版本和 evidence 反向引用。
3. 时间质量模型、时钟偏移采集、复合 Auditd 事件组装。
4. Host/User/Process/File/Registry/IP/Domain/Session 的 canonical identity 与 alias。
5. 登录 Session、网络 Session 和敏感数据路径。
6. Windows 内存行为与注册表的真实采集/测试。
7. 三种隐蔽信道独立检测器和正常对照指标。
8. ATT&CK 固定版本知识库、技术映射依据和攻击链状态机。
9. 只读、证据优先、可失败恢复的多 Agent Harness。
10. Dataset Adapter 与至少一个公开数据集的可重复实验。
11. 规定角色齐全的 8+ 节点隔离靶场和 Ground Truth manifest。
12. 显式 Snapshot 演示模式、契约测试和端到端验收脚本。

## 8. 迁移建议

不要把去年源码直接复制到新仓库。可选择性迁移的只有：少量 Zeek/Wazuh 字段映射表、Neo4j 查询思路、图形组件视觉编码和页面信息架构。迁移时先为目标模块编写今年的契约测试，再人工搬运并改写实现；任何不能通过新 schema 和 evidence 校验的代码不进入主分支。

## 9. 最值得保留与最危险的部分

最值得保留的是端网融合后的图谱交互原型，因为它能快速形成第一条可见闭环。最危险的是“看起来完整”的 Mock 和硬编码归因：它们会让现场演示成功，却无法通过老师对数据来源、证据和可重复性的追问。今年的设计因此把证据可追溯和明确的运行模式放在 UI 美化之前。
